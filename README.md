# Kotocode Bot 🤖

Telegram-бот онлайн-школы **Котокод**. Присылает преподавателям напоминания о занятиях.

---

## Что делает бот

Раньше бот был вторым местом, где хранились договорённости: менеджер вручную вбивал через диалог
допровод или перенос, бот держал это в собственной SQLite и сам слал напоминания. Данные при этом
дублировали журнал и расходились с ним.

Теперь **источник правды один — журнал** (`kotokod-teaching`, Django + PostgreSQL на той же машине).
Менеджер работает только в нём, а рассылку журнал ведёт сам, напрямую через Telegram Bot API.

Боту осталось две роли:

1. **Отвечать на три команды** преподавателю.
2. **Сообщать журналу, какому Telegram-нику соответствует числовой `chat_id`.** Это нужно, потому что
   по `@нику` Bot API писать в личку не умеет, а `chat_id` администратор глазами не видит. Как только
   человек написал боту хоть что-нибудь, его аккаунт появляется в журнале в списке для привязки.

Собственной базы, ролей и планировщика у бота больше нет.

---

## Что приходит преподавателю

Рассылает **журнал**, не бот. Здесь — для понимания, что увидит человек.

| Когда | Что | Куда |
|---|---|---|
| 8:00 | Список занятий на сегодня, с пометками «замена» и «доп.урок» | личка |
| 21:00 | Незаполненные отчёты по проведённым занятиям | личка |
| сразу | Назначен / изменён / отменён доп.урок | личка + общий чат |
| сразу | Перенос занятия, отмена занятия | личка + общий чат |
| сразу | Назначена или снята замена — уведомляются обе стороны | личка + общий чат |

Напоминаний за 24 часа и за 1 час больше нет: расписание человек получает утренним списком.

Чтобы напоминания начали приходить, администратор должен привязать преподавателя к его
Telegram-аккаунту в журнале (`/admin/teachers` → карточка → поле «Telegram»). До привязки бот
на `/my` честно об этом скажет.

---

## Команды

| Команда | Описание |
|---|---|
| `/start` | Приветствие |
| `/help` | Список команд |
| `/my` | Мои занятия на ближайшую неделю |

Команды работают **только в личных сообщениях** — в групповом чате бот их игнорирует.
Ролей у бота нет: кому и что слать, решает журнал.

## Стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.11 |
| Telegram | python-telegram-bot 20.7 |
| HTTP-клиент | httpx 0.25.2 (версия привязана жёстко: 0.27.x несовместим с PTB 20.7) |
| Конфигурация | python-dotenv |
| Тесты | pytest |
| Деплой | systemd (Ubuntu 22.04) |

Хранилища нет. Планировщика нет — расписанием занимается Celery в журнале.

## Установка

Требования: VPS с Ubuntu 22.04, Python 3.11, работающий рядом журнал.

```bash
git clone https://github.com/ReyTayler/kotocode-bot.git
cd kotocode-bot
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env
mkdir -p logs
```

`.env`:

```env
BOT_TOKEN=токен_от_BotFather
JOURNAL_API_URL=http://127.0.0.1:8000
BOT_SERVICE_TOKEN=общий_секрет_с_журналом
TIMEZONE=Europe/Moscow
LOG_LEVEL=INFO
```

`BOT_TOKEN` — **тот же токен**, что прописан в `.env` журнала: рассылку ведёт журнал, а бот тем же
токеном принимает сообщения. Telegram это допускает — ограничение на один процесс касается только
получения обновлений (`getUpdates`), которым занимается исключительно бот.

`BOT_SERVICE_TOKEN` — общий секрет с журналом, должен совпадать в обоих `.env`. Служебные эндпоинты
журнала дополнительно закрыты в nginx правилом `allow 127.0.0.1`, поэтому бот обязан жить на той же
машине.

Автозапуск:

```bash
cp systemd/kotocode-bot.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now kotocode-bot
systemctl status kotocode-bot
```

## Эксплуатация

```bash
systemctl status kotocode-bot        # статус
journalctl -u kotocode-bot -f        # логи
systemctl restart kotocode-bot       # после обновления
```

Обновление:

```bash
cd /home/kotocode/kotocode-bot && git pull
source .venv/bin/activate && pip install -r requirements.txt
systemctl restart kotocode-bot
```

Тесты: `pytest tests/ -v`

## Диагностика

**Преподаватель не получает напоминаний.** Проверять нужно в журнале, а не здесь: раздел
«Уведомления» (группа «Система») показывает журнал доставки со статусами и текстом ошибки. Частые
причины: аккаунт не привязан к преподавателю; человек заблокировал бота (журнал снимает привязку сам
и показывает причину в карточке); не работает `journal-celery-beat`.

**`/my` отвечает «аккаунт не привязан».** Администратор ещё не выбрал этот Telegram-аккаунт в
карточке преподавателя. Аккаунт появляется в списке для привязки только после того, как человек
написал боту хотя бы одно сообщение.

**Бот молчит на все команды.** `journalctl -u kotocode-bot -f`. Если в логах ошибки обращения к
журналу — проверить, что журнал поднят и что `BOT_SERVICE_TOKEN` совпадает в обоих `.env`.
