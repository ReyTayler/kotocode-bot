# Kotocode Bot 🤖

Telegram-бот для онлайн-школы **Котокод**. Решает проблему неучтённых допроведов и переносов уроков — фиксирует назначения, уведомляет преподавателей и напоминает о предстоящих мероприятиях автоматически.

---

## Зачем нужен бот

В школе регулярно возникают ситуации:
- Ученик пропустил урок → преподавателю назначают **допровед** (дополнительный урок для отработки пропуска)
- Урок не состоялся → менеджер договаривается о **переносе** на другое время

Раньше все договорённости оставались только в переписке чата и терялись. Бот решает эту проблему: менеджер фиксирует назначение через бота, преподаватель получает уведомление, а перед мероприятием приходят автоматические напоминания.

---

## Возможности

### Для менеджеров
- Назначить допровед или перенос через удобный шаблон с превью перед сохранением
- Редактировать любое поле назначенного события
- Просмотреть список всех активных событий с быстрыми командами отмены и редактирования
- Фильтровать события по конкретному преподавателю
- Отменить событие — преподаватель получит уведомление в личку

### Для преподавателей
- Получать личное уведомление при назначении, изменении и отмене допровода/переноса
- Получать напоминания за 24 часа и за 1 час до мероприятия (в общий чат и в личку)
- Просматривать свои назначения командой `/my`

### Автоматически
- Напоминания срабатывают точно в нужное время
- При изменении даты события напоминания автоматически пересчитываются
- При перезапуске бота все запланированные напоминания восстанавливаются из БД
- Прошедшие события автоматически архивируются через 2 часа после проведения

## Роли и права доступа

Система построена на флаговой модели — один пользователь может одновременно иметь несколько ролей. Например, преподаватель может также быть менеджером.

```
Супер-админ 👑
    └── Управляет администраторами
    └── Передаёт свои права другому человеку
        └── Администратор 🔧
                └── Управляет менеджерами и преподавателями
                    └── Менеджер 📋
                            └── Назначает допроведы и переносы
                                └── Преподаватель 👨‍🏫
                                        └── Просматривает свои назначения
```

Все роли управляются **через самого бота** — без правки кода и конфигов. Каждый пользователь видит только те команды, которые доступны его ролям. При нескольких ролях команды объединяются.

### Передача прав супер-админа
Права супер-админа передаются командой `/transfer` с подтверждением. После передачи источником правды становится БД, а не `.env` файл. В аварийной ситуации достаточно изменить `SUPERADMIN_ID` в `.env` и перезапустить бота.

## Команды

### Общие (все роли)
| Команда | Описание |
|---|---|
| `/start` | Приветствие и список всех активных ролей |
| `/help` | Список доступных команд |

### Преподаватель
| Команда | Описание |
|---|---|
| `/my` | Мои назначенные события |

### Менеджер
| Команда | Описание |
|---|---|
| `/add_doproved` | Назначить допровед |
| `/add_perenos` | Назначить перенос |
| `/cancel ID` | Отменить событие по номеру |
| `/cancel_ID` | Отменить событие кликом из списка |
| `/list` | Все активные события |
| `/list @username` | События конкретного преподавателя |
| `/edit_ID` | Редактировать событие кликом из списка |
| `/teachers` | Список преподавателей |

### Администратор
| Команда | Описание |
|---|---|
| `/addmanager @username` | Назначить менеджера |
| `/removemanager @username` | Снять менеджера |
| `/managers` | Список менеджеров |
| `/addteacher @username` | Зарегистрировать преподавателя |
| `/removeteacher @username` | Снять преподавателя |
| `/users` | Все пользователи бота по ролям |
| `/admins` | Список администраторов |

### Супер-админ
| Команда | Описание |
|---|---|
| `/addadmin @username` | Назначить администратора |
| `/removeadmin @username` | Снять администратора |
| `/transfer @username` | Передать права супер-админа |

## Установка и деплой

### Требования
- VPS с Ubuntu 22.04
- Python 3.11
- SQLite 3.35+ (для поддержки `DROP COLUMN`)
- 512 МБ RAM (рекомендуется 1+ ГБ)

### 1. Клонирование репозитория

```bash
git clone https://github.com/твой_username/kotocode-bot.git
cd kotocode-bot
```

### 2. Виртуальное окружение и зависимости

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Конфигурация

```bash
cp .env.example .env
nano .env
```

Заполнить переменные:

```env
BOT_TOKEN=токен_от_BotFather
GENERAL_CHAT_ID=-100xxxxxxxxxx
SUPERADMIN_ID=твой_telegram_id
TIMEZONE=Europe/Moscow
LOG_LEVEL=INFO
```

**Как узнать нужные значения:**
- `BOT_TOKEN` — создать бота у [@BotFather](https://t.me/BotFather), команда `/newbot`
- `GENERAL_CHAT_ID` — добавить [@userinfobot](https://t.me/userinfobot) в группу, он напишет ID
- `SUPERADMIN_ID` — написать [@userinfobot](https://t.me/userinfobot) в личку, он покажет твой ID

### 4. Создание папок

```bash
mkdir -p data logs
```

### 5. Проверка запуска

```bash
source venv/bin/activate
python main.py
# Ctrl+C для остановки
```

### 6. Автозапуск через systemd

```bash
# Копируем unit-файл (при необходимости меняем User= внутри)
cp systemd/kotocode-bot.service /etc/systemd/system/

# Активируем
systemctl daemon-reload
systemctl enable kotocode-bot
systemctl start kotocode-bot

# Проверяем статус
systemctl status kotocode-bot
```

## Первый запуск бота

1. Написать боту `/start` — бот зарегистрирует тебя как супер-админа
2. Добавить администраторов: `/addadmin @username`
3. Попросить всех сотрудников написать боту `/start` — они появятся в системе
4. Выдать роли: `/addmanager @username`, `/addteacher @username`
5. Добавить бота в общий чат группы и выдать ему права **администратора** (иначе не сможет отправлять сообщения в чат)

## Как работают напоминания

```
Менеджер добавляет допровед на 20.05 в 15:00
        │
        ▼
APScheduler планирует два задания на точное время:
├── 19.05 в 15:00 — напоминание за 24 часа
└── 20.05 в 14:00 — напоминание за 1 час
        │
        ▼
В нужное время бот отправляет:
├── Сообщение в общий чат с тегом @преподавателя
└── Личное сообщение преподавателю
```

При перезапуске бота все активные напоминания восстанавливаются из БД. При изменении даты события старые напоминания отменяются и планируются новые.

---

## База данных

Две таблицы:

**`users`** — все пользователи, когда-либо написавшие боту. Хранит `telegram_id`, `username`, `full_name` и четыре независимых булевых флага ролей: `is_superadmin`, `is_admin`, `is_manager`, `is_teacher`. Один пользователь может иметь несколько ролей одновременно.

**`events`** — все события (допроведы и переносы). Хранит тип, данные преподавателя, группу, номер урока, время, детей, комментарий, статус и флаги отправленных напоминаний.

Статусы событий: `active` → `done` (автоматически через 2ч после времени проведения) или `cancelled` (через `/cancel`).

## Безопасность

- Все команды работают **только в личных сообщениях** — в групповом чате бот игнорирует команды
- Логика ролей сосредоточена в `RoleService` — единственном месте где определяются права
- Проверка прав происходит при каждом обращении через декоратор `@require_role`
- Callback-кнопки проверяют права явно внутри обработчика
- Глобальный `error_handler` перехватывает все исключения и уведомляет супер-админа
- Файл `.env` исключён из репозитория через `.gitignore`
